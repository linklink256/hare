# 子代理标题右侧显示本轮耗时（源码，未打包）

## 显示与口径
- 团队面板、团队抽屉中，子代理标题右侧显示 M:SS，达到1小时改 H:MM:SS；无旧记录时显示 —，不补算不存在的数据；领队行不加耗时。
- 从通过TeamExecutionGate并发准入开始，用单调时钟记时，覆盖一轮模型+工具执行；排队时间不计。正常、失败、取消均冻结，下一次派活重新从0开始，不是从创建成员开始累加。
- 审批暂停返回AwaitingApproval结束当前执行轮，等待人工审批不计入；审批续跑视为新一轮。后台标题/建议请求、持久化耗时不计入。这不是任务板任务从pending到done的工期。
- 只在面板/抽屉已有可见订阅期间每秒刷新；没有全局定时器、轮询DB或读取消息预览。关闭面板停止订阅。

## 数据与边界
- TeamMember/实体增加nullable lastRunElapsedMillis，数据库33->34自动迁移；旧记录NULL，单列UPDATE，不用旧成员整行回写。耗时保存后可跨App重启保留。
- Gate持有活跃计时和最多64项已完成计时小缓存，避免Room观察延迟/保存失败时回退到旧数字；不按历史成员数无限增长。
- 保存失败在ChatService报告错误，不阻塞finally释放并发名额；失败结果可暂存在64项缓存，重启后不能承诺恢复未保存值。进程被系统直接杀死的未完成轮不伪造最终耗时。
- 不把能看耗时升级为子代理领队工具权限；并发上限和工具鉴权保持不变。

- 独立Kotlin/JUnit：27项全部通过（旧gate9，新duration10，时钟/格式8），编译384MiB、测试128MiB，12.0秒；最低采样MemAvailable2390196KiB。
- 覆盖准入前无计时、正常/取消/失败回调、排队取消不写假数据、新轮重置、保存失败释放、保存期间冻结、不丢活跃计时、64缓存上限及小时/负数边界。
- SQLite内存fixture使用33.json真实表结构，增加nullable列后旧行/角色/状态/创建时间保留，单列更新正确，已删除成员不复活；UI布线/无预览读取/差异空白检查通过。
